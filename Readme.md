# SamplePlugin

This project is a **template for building a ComicRack .NET plugin**, not a useful plugin by itself. Use it as a starting point and adapt the sample code, resources, and package metadata for your plugin.

.NET Plugins are a new plugin type that can be used in [ComicRack Community Edition](https://github.com/maforget/ComicRackCE), in addition to the existing IronPython plugins. It runs natiely using the same ecosystem that ComicRack itself uses. This makes it easier to create, test, debug. See the related [wiki page](https://github.com/maforget/ComicRackCE/wiki/.NET-plugin) for more information on the plugin engine.

The project targets **.NET Framework 4.8**. `Directory.Build.props` configures the build, and `Directory.Build.targets` adds steps that place the generated plugin files in a plugin-specific folder under the ComicRack scripts directory.

## Build modes

Set `IsSourcePlugin` in `Directory.Build.props` to choose the plugin output:

| `IsSourcePlugin` | Output |
|---|---|
| `false` | A compiled plugin. The built assembly is copied to the plugin folder. In Debug builds, its PDB is copied too if available. |
| `true` | A source plugin. Project `.cs` files are copied instead of the compiled assembly, and a `.csplugin` marker file is generated. |

Both modes generate `package.ini`, copy resolved NuGet package DLLs, and zip each immediate subfolder of `Resources` into a ZIP file in the plugin folder. Image copying is also enabled in source mode; in compiled mode it is controlled by `CopyResourcesImage`.

## Resources and translations

Keep resources under the project’s `Resources` directory. Add embedded resources to the project file as `EmbeddedResource` items; for example, this project declares `Resources\SamplePlugin.png` as an embedded resource.

Place translation files in language-specific subfolders, such as `Resources\fr` or `Resources\es`. The build zips **every immediate subfolder** of `Resources`, regardless of the folder name, in both plugin modes. Keep language files in those folders so they are included in the corresponding ZIP.

Supported image files are copied from `Resources` when image copying is enabled: `.png`, `.jpg`, `.jpeg`,`.bmp`, and `.gif`.

## What the build targets do

`Directory.Build.targets` adds steps around the normal project build:

1. **Resolve the output folder.** The plugin folder is `ScriptFolder\PluginOutputName`. If `ScriptFolder` is empty, the project’s build output folder (`TargetDir`) is used.
2. **Create the plugin folder** after the normal build output is copied.
3. **Choose the plugin payload** based on `IsSourcePlugin`:
   - Compiled mode copies the built assembly and, for Debug builds, its PDB if present.
   - Source mode copies `.cs` files, excluding `obj`, `bin`, and `Properties`.
4. **Zip resource subfolders.** Every immediate subfolder under `Resources` is zipped, regardless of build mode.
5. **Copy image resources.** Images are copied in source mode or when `CopyResourcesImage` is `true`.
6. **Generate `package.ini`** from the configured plugin metadata. Empty metadata values are omitted.
7. **Generate a `.csplugin` marker** in source mode. It includes resolved package references, framework references, and the configured language version.
8. **Copy NuGet package DLLs** marked for local copying into the plugin folder.
9. **Clean plugin output.** The clean targets remove the plugin output folder. This can delete files in that folder that were not generated by the build.

## Configuring `Directory.Build.props`

Change these properties in `Directory.Build.props` to customize the build:

| Property | What it affects |
|---|---|
| `ComicRackPath` | Location of the ComicRack installation. The build uses it to find `ComicRack.Engine.dll` and `ComicRack.Plugins.dll`. Set it to the installation directory on your machine. |
| `ScriptFolder` | Base folder where plugin output is placed. The plugin is placed in a subfolder named by `PluginOutputName`. Set it to your ComicRack scripts directory, or leave it empty to use the project’s normal build output folder. |
| `IsSourcePlugin` | Selects the output mode. Set to `false` for a compiled plugin or `true` for a source plugin and its `.csplugin` marker. |
| `CopyResourcesImage` | In compiled mode, controls whether supported images under `Resources` are copied to the plugin folder. Set to `true` or `false`. Images are always copied in source mode. |
| `PluginName` | Plugin name written to `package.ini`; also determines the plugin output folder name. If empty, the output folder name falls back to the project’s `AssemblyName`. |
| `PluginDescription` | Description written to `package.ini`. Leave empty to omit it. |
| `PluginAuthor` | Author written to `package.ini`. Leave empty to omit it. |
| `PluginImage` | Image filename written to `package.ini`. Leave empty to omit it; otherwise, ensure the image is included in the plugin output. |
| `PluginVersion` | Version written to `package.ini`. Leave empty to omit it. |
| `PluginHelpLink` | Help link written to `package.ini`. Leave empty to omit it. |
| `PluginKeepFiles` | `KeepFiles` value written to `package.ini` (for example, `user.ini`). Leave empty to omit it. Note that the build’s Clean target does not preserve files based on this value. |

For Debug builds, the props file sets `DebugType` to `portable`, enabling PDB generation. It also references PolySharp to help use newer C# language features while targeting .NET Framework 4.8.

## Overriding properties from the command line

MSBuild properties passed with `-p` override the values in `Directory.Build.props` for that build. This lets you switch plugin modes or output folders without editing the props file.

Using MSBuild:

```powershell
msbuild .\SamplePlugin\SamplePlugin.csproj -t:Rebuild -p:Configuration=Debug -p:IsSourcePlugin=true '-p:ScriptFolder=C:\Exports\Another Export Path'
```

Or using the .NET CLI:

```powershell
dotnet build .\SamplePlugin\SamplePlugin.csproj -t:Rebuild -p:Configuration=Debug -p:IsSourcePlugin=true '-p:ScriptFolder=C:\Exports\Another Export Path'
```

Add more `-p:PropertyName=Value` arguments to override other properties, such as `PluginName` or `CopyResourcesImage`. Use an absolute `ScriptFolder` path to avoid ambiguity about how a relative path is resolved.

## Getting started

1. Update the ComicRack installation and scripts paths for your environment. The provided values should work if you've used default locations for install & data folders.
2. Set the plugin metadata and choose `IsSourcePlugin`.
3. Put embedded resources and language translation files under `Resources`, adding embedded files to the project as `EmbeddedResource` items.
4. Add or modify the plugin code and resources.
5. Build the `SamplePlugin` project. The generated plugin files are copied to the configured plugin folder.
